# Windows 实现任务与验收

此分支含 Mac 1.1.8 可读源码与规则参考。Windows 桌面壳、虚拟网卡和系统代理适配仍需实现。用 [Mac 界面与功能规格](MAC-PRODUCT.md) 确认用户看到的行为。

## 第一阶段交付

1. 建立 Windows 客户端的主进程、受限 preload、界面入口和打包入口，给出一个可运行的开发命令。初版界面实现首页的连接状态和线路列表，支持本机模拟模式。
2. 在主进程做连接控制器，将内核控制、受管连接关闭、持久化选择和状态更新接到 `src/claude-exit-guard.cjs` 的 `Guard`。此阶段先用测试代理确认启动、故障、恢复、取消及确认不同出口能走同一状态机。
3. 做 Windows 内核启动、退出、权限和系统接管适配。正常启动前保持保护范围内的流量拦截，完成接管并验证后再放行。确认断开和失败恢复能按设计还原系统设置。真机接管未过验收时，界面明确显示测试状态。
4. 交付一个最小真机测试路径，给出普通网页、Codex 独立代理和 Claude 检测页的验证结果。系统 API 与权限行为以当前 Windows 环境实测为准。

## 源码接线

| 能力 | 入口与要点 |
| --- | --- |
| VLESS 解析、配置、字节统计 | `src/vless-tools.cjs`、`src/leyra-claude-vless.cjs`。入口配置保存时保护凭据，Windows 的网卡枚举需适配 |
| 自动识别 | `src/detect-vless-exit.cjs`。传入本机 Mihomo 可执行文件路径，临时启动仅回环的认证探测入口，从候选节点读取 TLS 检测结果。探测失败保留节点。自动登记成功后保留当前选用路线 |
| 备用状态机 | `Guard` 的 `probe`、`gate`、`drain`、`saveChoice`、`update` 等依赖由主进程注入。默认拒绝，初次或切换放行前复核，使用选择器状态和已有连接列表核对保护是否生效 |
| 规则生成 | `src/ai-network-script.js`、`src/leyra-routing.cjs`、`src/mobile-rules.json`。对照 Mac 的域名和进程优先级，将 `.app` 路径改为 Windows 所需的进程名/可执行文件路径处理 |
| 原地加载与 IPC 参考 | `mac-overlay/guard-main.cjs` 与 `mac-overlay/patch.rb` 是 Mac 接线参考。Windows 单独实现配置加载、权限和平台 API |
| 诊断误报与名称 | `isAuthenticatedProbeLog`、`isAuthenticatedProbeConnection` 识别已认证的内部探测。用 Windows 内核实际日志与连接元数据验证；`src/process-labels.cjs` 只做 UI 标签映射 |
| 时区 | `src/leyra-timezone.cjs` 提供 Mac 恢复逻辑参考。Windows 实现自己的时区标识映射、权限、恢复和失败处理 |
| 状态与界面 | `design/guard-ui.js`、`design/guard.css`、`design/timeline.js` 描述 Mac 本地状态和 UI；把同一套状态模型接到 Windows 界面 |

随后按页面规格接入节点、分流规则、诊断、设置和账号授权。用 Windows 真机完成安装、运行、更新、卸载的网络恢复验证之后再生成供客户下载的安装包。

## 账号对接与数据

`api-reference/api.mjs` 与 `api-reference/api.test.mjs` 描述现有服务端协议。优先跑内存测试，接现网前核对协议版本。

- 注册和登录为 `/v1/auth/signup`、`/v1/auth/login`。邮箱验证、刷新和注销按 API 代码与测试执行。
- `/v1/me` 返回订阅和授权。服务端响应决定试用起止，试用到期后的受保护流量应拦截。
- `/v1/devices` 用于激活设备。当前校验代码中 Windows 使用 `platform: "windows"` 与 `client: "clash-verge-rev"`。授权后由服务端提供设备配置。
- 使用 Windows 提供的凭据存储，保护账号、订阅令牌、节点链接和密码。公开仓库、安装包和诊断只用测试数据。发布前检查第三方字体、内核及依赖的许可和随附声明。

## 真机验收

| 场景 | 可观察的通过标准 |
| --- | --- |
| 正常连接 | 浏览器请求与 Claude 桌面流量经受保护路径，实测出口和登记 IP 一致，首页随后显示守护中 |
| 线路异常 | 关闭或使上游不可达，检查受管新旧流被拦；普通网页继续访问，Codex 经独立代理仍可收到回复 |
| 同 IP 恢复 | 恢复原线路或可达的同 IP 备用，核验通过后自动恢复 |
| 不同 IP | 在列表显示可用线路和新旧 IP。取消保持选择；确认后重新实测。候选出口漂移不放行 |
| 所有线路失败 | 显示原因和下一次复查，持续拦截受管请求，普通网站与 Codex 路径正常 |
| 接管覆盖 | 验证 Claude 浏览器、桌面和子进程、自定义域名和程序；另外检查 DNS、IPv6、QUIC、网络切换、睡眠恢复和异常退出时的绕行 |
| 诊断 | 内部探测不产生绕行误报或人工流量统计。真实直连应能上报。名称修正、搜索和时间条显示符合 Mac 规格 |
| 试用和设置 | 以测试账号检查注册、邮箱验证、到期拦截、永久授权恢复、时区调整与恢复。验证重启和卸载后的设置 |
| 发布前 | 记录系统版本、权限、每项实测结果和失败点。保存可回滚的安装与卸载路径 |

Mac 1.1.8 已实测诊断名称、VLESS 实际出口、备用线路可选和普通站点访问。Mac 故障注入验证过拦截和自动恢复，轮询间隔 5 秒，单次探测超时 4.5 秒。Windows 的实际延迟、权限和异常退出行为都要重测。
